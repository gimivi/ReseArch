App 3D (TJS)

TJS mostra modelli tridimensionali, nuvole di punti e panorami a 360° in una scena navigabile. Più modelli collegati allo stesso oggetto si caricano insieme nella stessa scena. La spec del modello dice dove metterli; luci, camere e ambiente si regolano nel pannello e si salvano nella spec.

File ammessi

Il caricatore si sceglie dall'estensione del file, non dalla spec.

Formati letti da TJS e template consigliato

.obj (+ .mtl)Mesh; il file .mtl dei materiali va nella stessa cartella con lo stesso nome.OBJ
.drcDraco compresso: nuvola di punti colorata o mesh.DRC

.wrl .vrml .wrzModello VRML, anche compresso.GLTF

File senza materiali. Se il file non dà un materiale a una superficie, il pannello le dà il materiale clay (grigio chiaro e opaco) invece del materiale di ripiego del caricatore, spesso metallico o nero. Succede con: glb/gltf senza materiale, obj senza il suo .mtl, wrl senza Appearance, ply e drc di superfici senza colori. Colore e lucentezza del clay si regolano nel pannello Ambiente.

Per i formati senza template dedicato basta il template GLTF: conta solo il blocco transform. Si può anche scegliere Nessun file (dati dal flow): la scena parte vuota e un flow la riempie.

I template

Modelli → colonna Spec → tendina Template → Valida → Salva spec → salva la tabella

Il template precompila la spec. Poi la puoi modificare a mano: deve restare JSON valido (virgolette doppie, niente virgola dopo l'ultimo elemento).

GLTF base

Per modelli .glb/.gltf e, in pratica, per ogni modello di cui vuoi solo regolare la posizione.

{
  "type": "gltf",
  "transform": {
    "position": [0, 0, 0],
    "rotation": [0, 0, 0],
    "scale":    [1, 1, 1]
  }
}
  • type: solo un promemoria. Cambiarlo non cambia nulla.
  • transform: posizione, rotazione e scala del modello nella scena; vedi Posizione e rotazione. Se manca, il modello resta com'è nel file.

OBJ base

Uguale a GLTF, con "type": "obj". Il file .mtl si carica da solo se ha lo stesso nome del .obj.

{ "type": "obj", "transform": { "position": [0, 0, 0], "rotation": [0, 0, 0], "scale": [1, 1, 1] } }

DRC base

Per nuvole di punti .drc (e .ply). I colori dei punti vengono dal file.

{ "type": "drc", "transform": { "position": [0, 0, 0], "rotation": [0, 0, 0], "scale": [1, 1, 1] } }

Dimensione e forma dei punti non si scrivono qui a mano: si regolano nel pannello Materiale e si salvano con Salva su modello (blocco pointsLineStyle, più sotto).

Pano360 base

Per una foto equirettangolare .jpg/.png: l'immagine riveste l'interno di una sfera e tu sei al centro.

{
  "type": "pano360",
  "raggio": 10,
  "meridiani": 60,
  "paralleli": 40,
  "transform": { "position": [0, 0, 0], "rotation": [0, 0, 0], "scale": [1, 1, 1] }
}
Campi del template Pano360
CampoPredefinitoEffetto
raggio10Grandezza della sfera. Conta se nella scena ci sono anche altri modelli o misure.
meridiani60Suddivisioni in orizzontale: più alto = sfera più liscia ma più pesante.
paralleli40Suddivisioni in verticale.
transform.rotation[0,0,0]Utile per girare il panorama: il secondo valore ruota attorno alla verticale.
panoDepthassenteFacoltativo: la mappa delle distanze della foto, per misurare sul panorama. { "url": "…/depth.exr", "scale": 1 }: url del file EXR prodotto da ComfyUI (MoGe o DA2, nodo ReseArch Depth Output), scale = fattore di calibrazione (1 = non calibrato, distanze relative).

Con panoDepth, Collima e Misura danno punti nello spazio e non sulla sfera. Per i panorami creati da un flow la mappa si associa con i nodi TJS/Panorama/*.

Posizione e rotazione

Il blocco transform sposta il modello senza modificare il file. Serve soprattutto per mettere d'accordo più modelli nella stessa scena.

  • position [x, y, z]: spostamento, nelle unità del file (di solito metri). In TJS l'asse Y è la verticale.
  • rotation [x, y, z]: rotazione attorno ai tre assi, in radianti, non in gradi.
  • scale [x, y, z]: ingrandimento per asse; usa tre valori uguali per non deformare.
Gradi → radianti
Gradi45°90°180°−90°
Radianti0.78541.57083.1416−1.5708

Casi frequenti

Esempi di transform
Situazionetransform
Il modello è "sdraiato": viene da un programma con Z verticale (Rhino, CAD, molti rilievi) "rotation": [-1.5708, 0, 0]
Il file è in millimetri e appare 1000 volte troppo grande "scale": [0.001, 0.001, 0.001]
Il modello è lontanissimo dall'origine (coordinate geografiche) "position": [-X, -Y, -Z] con le coordinate del suo centro cambiate di segno

Blocchi salvati dal pannello

Altre voci della spec non si scrivono a mano: le crea il pannello 3D quando premi il suo pulsante di salvataggio. Il pannello aggiunge o sostituisce solo la sua voce e lascia intatto il resto della spec.

Voci della spec scritte dai pannelli di TJS
VocePannello → pulsanteContenuto
environmentAmbiente → Salva ambiente Griglia, sfondo e nebbia, tone mapping ed esposizione, ombre, occlusione ambientale (GTAO), illuminazione da immagine HDR, punti e linee predefiniti. Dentro: baseLight (luce ambiente, sole con azimut ed elevazione, ombra del sole, pavimento per le ombre, ambiente neutro) e clay (vista clay, anche i trasparenti, colore, ruvidità, velatura, riflessi).
lightsLuci → Salva Le luci create: tipo, colore, intensità, posizione, bersaglio, ombre.
camerasCamere → Salva camere di questo modello Punti di vista con nome: posizione, rotazione, angolo di campo.
clipConfigsSezioni → Salva configurazione corrente Piani di sezione già pronti da richiamare: posizione, parte tenuta, colore del riempimento, sezione opaca.
collimatedPointsPunti collimati → salva Punti presi sul modello, per esempio per allineare due rilievi. Quelli presi su un panorama con mappa delle distanze conservano anche la distanza letta.
pointsLineStyleMateriale → Salva su modello Dimensione e forma dei punti, spessore delle linee di questo modello.

Con più modelli nella scena: ambiente, sezioni e punti collimati si leggono dal primo modello che li contiene. Luci e camere invece appartengono ciascuna al proprio modello: quando salvi, scegli in quale.

Il pannello parte dalla spec letta all'apertura dell'oggetto. Se nel frattempo hai modificato la spec dalla modale Modelli, ricarica l'oggetto prima di salvare dal pannello, altrimenti le tue modifiche vengono sovrascritte.

Esempio di spec dopo qualche salvataggio 
{
  "type": "gltf",
  "transform": { "position": [0, 0, 0], "rotation": [-1.5708, 0, 0], "scale": [1, 1, 1] },
  "environment": { "grid": { "visible": false }, "rendering": { "exposure": 1.1, "shadowEnabled": true },
                   "clay": { "enabled": true, "includeTransparent": false, "color": "#d8d4cc" } },
  "cameras": [ { "name": "Ingresso", "type": "Perspective", "fov": 50,
                 "position": { "x": 4, "y": 1.6, "z": 9 }, "rotation": { "x": 0, "y": 0.4, "z": 0 } } ]
}

I blocchi reali contengono più campi: è normale, e non serve toccarli a mano.

Problemi comuni

  • Scena vuota. In Modelli guarda la colonna File?: se dice MANCANTE il file non è nel percorso indicato.
  • Non vedo il modello ma è caricato. Probabilmente è lontano o enorme: usa le viste predefinite della barra o correggi position/scale.
  • Modello sdraiato o capovolto. Ruota di −90° sull'asse X (vedi sopra).
  • Nuvola di punti tutta bianca o con punti enormi. Regola i punti nel pannello Materiale e salva sul modello.
  • Il salvataggio della spec viene rifiutato. Premi Valida: di solito manca una virgola o c'è una virgola di troppo.
  • Il modello si apre tutto grigio chiaro. La spec ha environment.clay.enabled = true: spegni la vista clay in Ambiente e premi Salva ambiente. Se resta grigio, il file non ha materiali.
  • Avvisi. Il menu del pannello a destra → Avvisi modelli elenca le correzioni fatte in automatico (per esempio normali mancanti, che impediscono le ombre).
