Cartografia (OLY)

OLY mostra mappe con OpenLayers: un fondo (OpenStreetMap, carta topografica, foto aeree) e sopra i layer dell'oggetto, uno per modello: file GeoJSON, KML, GPX, GeoTIFF, immagini georiferite e servizi WMS scelti dall'amministratore. Coordinate anche nei sistemi italiani (Gauss-Boaga, RDN2008, UTM). Il modulo è in beta.

Preparare i file

  1. Vettoriali: esporta in GeoJSON (meglio in WGS84, EPSG:4326), KML o GPX. Da QGIS: Esporta → Salva elementi come….
  2. Raster: GeoTIFF, meglio COG in EPSG:3857 per i file grandi (gdalwarp -t_srs EPSG:3857 -of COG ingresso.tif uscita.tif).
  3. Mappe storiche o disegni: un'immagine con i suoi estremi (extent) nella spec.
  4. Carica i file in una sottocartella del WP e crea un modello per ciascuno, con il template adatto.

Estensioni ammesse: .geojson .json .kml .gpx .tif .tiff .jpg .png .webp.

Modelli e spec

La spec del primo modello dà la vista iniziale, il sistema delle coordinate e il fondo (template Cartografia — Base); ogni modello con un file o un servizio diventa un layer.

{
  "view": { "center": [12.4924, 41.8902], "zoom": 16, "rotation": 0 },
  "crs": "EPSG:3004",
  "base": "osm",
  "views": [ { "name": "Foro", "center": [12.4853, 41.8925], "zoom": 18, "rotation": 0, "base": "esri-imagery", "layers": { "m12": true } } ]
}
  • view.center = [longitudine, latitudine] in gradi; zoom 0 (mondo) … 22; rotation in gradi.
  • crs = sistema delle coordinate del footer; base = id del catalogo o "none".
  • views si scrive dalla finestra Viste → Salva nel modello (livello autore).

Servizi esterni

Fondi e servizi stanno nel catalogo lib/map-services.json, curato dall'amministratore: nei modelli si indicano solo per id. Oggi: osm, opentopomap, esri-imagery (fondi), catasto-ade (Catasto), pcn-ortofoto-2012 e pcn-igm25000 (Geoportale Nazionale).

  • Il Catasto si vede solo a scala di dettaglio (quartiere, isolato). Un clic sulla mappa mostra foglio e particella del punto.
  • Catasto e Geoportale Nazionale passano dal server della piattaforma (il Geoportale risponde solo in http, il Catasto non si lascia leggere dal browser): sono un po' più lenti dei fondi, ma si esportano in PNG.

Problemi comuni

  • Il layer non compare. Nella finestra Layer la riga gialla spiega l'errore; un GeoJSON in Gauss-Boaga o UTM senza crs nel file ha bisogno di dataProjection nella spec.
  • Il GeoTIFF è sfocato. Non è in EPSG:3857: viene letto ridotto. Convertilo in COG EPSG:3857.
  • «Il servizio non ha risposto» nella finestra Proprietà o una riga gialla per Catasto/Geoportale: il servizio esterno è lento o fermo; riprova più tardi.
  • Il catasto è vuoto. Avvicinati: il servizio disegna solo a scala di dettaglio.
