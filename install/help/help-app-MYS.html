Tabelle del database (MYS)

MYS mostra una tabella del database della piattaforma, con ricerca, filtri e, se abilitata, modifica delle righe che viene salvata davvero. È la scelta giusta per schedature e censimenti curati da più persone.

Prima di iniziare

Per sicurezza MYS legge solo le tabelle che l'amministratore ha registrato nel server (file api/grid_schema.php). Per ogni tabella l'amministratore decide:

  • quali colonne si possono leggere, filtrare e ordinare;
  • se la tabella si può modificare (aggiungere, cambiare, eliminare righe);
  • quante righe al massimo si possono chiedere in una volta.

Se la tua tabella non è registrata, chiedi all'amministratore. La spec da sola non basta ad aprire una tabella.

Il template "MySQL Tabulator" base

Modello Nessun file (dati dal flow); tutto è nella spec.

{
  "table": "Schedatura_Teatri",
  "fields": ["*"],
  "where":   [ { "field": "Regione", "op": "=", "value": "Lazio" } ],
  "orderBy": [ { "field": "Nome", "dir": "asc" } ],
  "limit": 200,
  "pageSize": 25,
  "pkField": "id",
  "searchFields": ["Nome", "Città"],
  "columns": [
    { "field": "id",   "title": "#",    "width": 60, "frozen": true },
    { "field": "Nome", "title": "Nome", "width": 220 },
    { "field": "AnnoApertura", "title": "Apertura" },
    { "field": "Esistente", "title": "Esiste", "formatter": "boolean" }
  ],
  "busKey": "id"
}
Campi della spec MYS
CampoPredefinitoEffetto
table—Obbligatorio. Nome della tabella registrata.
fields["*"]Colonne da leggere.
wherenessunoFiltri sempre attivi, es. solo una regione. Operatori: = != < <= > >= like (con %: "Roma%"). Si sommano a ricerca e filtri successivi.
orderBy—Ordinamento iniziale; dir = "asc" o "desc".
limit200Righe massime caricate.
pageSize25Righe per pagina.
pkFieldquello del serverColonna che identifica la riga. Serve per modificare ed eliminare.
searchFieldstutteColonne in cui cerca la casella di ricerca.
columnstutteColonne da mostrare: field, title, width, frozen (ferma a sinistra), formatter.
busKey—Campo scambiato con gli altri pannelli.

Formati di colonna (formatter)

  • "date", "datetime": data (e ora) all'italiana.
  • "money": due decimali.
  • "boolean": ✔ / ✗.
  • "badge": etichetta colorata; serve anche "colors": { "Sì": "#2e7d32", "No": "#c62828" }.

Più tabelle per lo stesso oggetto: un modello per tabella; il menu a sinistra del pannello passa dall'una all'altra.

Modificare i dati

Se la tabella è modificabile e tu hai almeno il livello di autore, compaiono la colonna delle azioni e il pulsante per aggiungere righe.

  • Doppio clic su una cella per modificarla, poi ✓ per salvare la riga o ✗ per annullare.
  • Il cestino elimina la riga, dopo una conferma.

Le modifiche vanno subito nel database e le vedono tutti. Non c'è un "annulla" dopo il salvataggio.

Altri pannelli

Con busKey la tabella parla e ascolta:

  • clic su una riga → gli altri pannelli sanno quale elemento è stato scelto (es. la mappa centra quel teatro);
  • un altro pannello sceglie lo stesso elemento (stesso campo, stesso valore) → la riga si evidenzia qui;
  • un altro pannello o un flow può mandare dei filtri o chiedere di ricaricare i dati.

Problemi comuni

  • "Tabella … non presente nella whitelist". La tabella non è registrata, o il nome in table è diverso (maiuscole comprese).
  • "Colonna non consentita", "Filtro non consentito", "Ordinamento non consentito". In fields, where o orderBy c'è una colonna che l'amministratore non ha abilitato per quell'uso.
  • Non posso modificare. La tabella è registrata in sola lettura, oppure il tuo livello non basta.
  • Mancano righe. Controlla limit e i filtri in where.
