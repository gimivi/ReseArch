Grafici (ECH)

ECH disegna grafici (barre, linee, torte, reti, alberi, calendari…) a partire da dati scritti nella spec, da un file o da una query sul database. Il grafico si esporta in PNG e dialoga con gli altri pannelli.

Il modo più semplice

  1. Crea il modello con Nessun file (dati dal flow) e il template Grafico — dati JSON inline.
  2. Crea l'oggetto con App ECH, collega il modello e aprilo.
  3. Dalla barra del pannello usa Sorgente dati e Layout grafico: modificano la spec per te e la salvano.

La spec a mano serve per i casi particolari. Ha quattro parti:

{
  "dataSource":      { … da dove vengono i dati … },
  "template":        "bar-basic",
  "templateConfig":  { … titolo, colori, legenda … },
  "optionOverrides": { }
}

Se un oggetto ha più modelli, ECH usa solo il primo.

Sorgente dati (dataSource)

Dati nella spec — template "Grafico — dati JSON inline" base

"dataSource": {
  "type": "json",
  "inline": [
    { "secolo": "XV",  "opere": 12 },
    { "secolo": "XVI", "opere": 31 }
  ],
  "mapping": { "category": "secolo", "value": "opere" }
}

Al posto di inline puoi mettere "url": "https://…/dati.json": il file viene letto all'apertura. Se ci sono entrambi, vale inline.

JSON a colonne

Alcuni servizi rispondono a colonne invece che a righe, per esempio Open-Meteo (si apre in una nuova finestra): { "hourly": { "time": [ … ], "temperature_2m": [ … ] } }. Due campi in più lo trasformano in righe:

"dataSource": {
  "type": "json",
  "url": "https://api.open-meteo.com/v1/forecast?latitude=41.8902&longitude=12.4922&hourly=temperature_2m,precipitation&timezone=Europe%2FRome&forecast_days=3",
  "path": "hourly",
  "columns": "long",
  "key": "time",
  "mapping": { "category": "time", "value": "value", "series": "variable" }
}
  • path: dove stanno i dati nella risposta, con i punti fra i livelli (es. data.items).
  • columns: "wide": una riga per ora con tutte le colonne (time, temperature_2m, …).
  • columns: "long": una riga per ora e per variabile (time, variable, value): con series: "variable" ogni variabile diventa una linea. key è la colonna che resta (se manca, la prima).

I dati si leggono a ogni apertura del pannello (o con Ricarica).

Per cambiare luogo o periodo mentre il grafico è aperto si usa un flow: il nodo Web/Open-Meteo/Forecast (coordinate dagli ingressi lat e lon, previsione o storico dal 1940) dà le righe già pronte per ECH/Chart/SetData; per altri servizi a colonne c'è Params/Data/Columns To Rows.

Open-Meteo è gratuito per usi non commerciali (circa 10.000 richieste al giorno) e chiede di citare la fonte: scrivi "Open-Meteo.com" nel sottotitolo del grafico.

CSV da un indirizzo

"dataSource": {
  "type": "csv_url",
  "url": "https://docs.google.com/spreadsheets/d/ID/export?format=csv&gid=0",
  "delimiter": ",",
  "hasHeader": true,
  "mapping": { "category": "Città", "value": "Visitatori" }
}

Comodo con un foglio Google pubblico: il grafico si aggiorna quando cambi il foglio e premi Ricarica.

Query sul database — template "Grafico — query MySQL" base

"dataSource": {
  "type": "mysql",
  "sql": "SELECT Regione AS category, COUNT(*) AS value FROM Schedatura_Teatri GROUP BY Regione",
  "params": [],
  "mapping": {}
}

Le query funzionano solo per l'amministratore: con un altro utente il server le rifiuta e il grafico resta vuoto. Sono ammesse solo query che iniziano con SELECT; i valori variabili vanno in params con un ? nella query.

Il mapping

Ogni tipo di grafico si aspetta dei nomi precisi (es. category e value). Il mapping dice quale colonna dei tuoi dati corrisponde a ciascun nome, così non devi rinominare i dati. Nelle query SQL puoi usare invece AS e lasciare il mapping vuoto.

La voce "Tema scuro / chiaro" del menu del pannello è solo un'anteprima e non si salva. Per salvarla usa Layout grafico.

Stile del grafico

Il grafico è disegnato da ECharts dentro un <canvas>: i fogli di stile CSS non arrivano lì dentro. Colori, caratteri, assi e sfondo si scrivono nella spec del modello, in due posti:

  • templateConfig: i campi della finestra Layout grafico (titolo, palette, legenda, tema scuro…). Basta per la maggior parte dei casi.
  • optionOverrides: tutto il resto, con le opzioni native di ECharts. Si scrive a mano nella Spec (JSON) del modello (finestra Modelli).

La palette dei colori

In Layout grafico si scrive come elenco di colori separati da virgola (#0066cc, #c62828, #2e7d32); nella spec diventa "colors": ["#0066cc", "#c62828", "#2e7d32"]. Vuota = palette di ECharts (diversa con il tema scuro). I colori si usano in ordine; se gli elementi da colorare sono più dei colori, si ricomincia dal primo. Che cosa riceve un colore dipende dal tipo di grafico:

Uso della palette per tipo di grafico
GraficoChi riceve i colori
Barre, Linee, Dispersione, RadarUna serie per colore: la prima serie il primo colore, e così via. Senza il campo series c'è una serie sola, quindi tutte le barre hanno il primo colore (per un colore per barra vedi la ricetta qui sotto).
TortaUna fetta per colore, nell'ordine dei dati.
ReteUna categoria (o livello) di nodi per colore; il primo colore è il livello 0.
Flussi (Sankey)Un nodo per colore; i flussi prendono il colore del nodo di partenza o di arrivo (opzione "Colore linee" in Layout grafico).
Treemap, RaggieraUn colore per ogni ramo del primo livello; i figli ne prendono una sfumatura.
Mappa di calore, CalendarioSolo i primi due colori: valore minimo → valore massimo, con le sfumature in mezzo.
IndicatoreUn colore per lancetta. Con le soglie, solo dalla Spec (JSON): "colors": [[0.3, "#2e7d32"], [0.7, "#f9a825"], [1, "#c62828"]] colora l'arco a fasce (0–30%, 30–70%, 70–100%).
AlberoLa palette non viene usata: per i colori serve optionOverrides.

Ricette con optionOverrides

Quello che scrivi viene unito alle opzioni preparate dal tipo di grafico: indichi solo ciò che cambia. Le chiavi sono quelle della documentazione di ECharts (echarts.apache.org → Documentation → Option).

"optionOverrides": {
  "backgroundColor": "#fafafa",
  "textStyle": { "fontFamily": "Titillium Web, sans-serif", "fontSize": 13 },
  "title":  { "left": "center", "textStyle": { "color": "#0066cc", "fontSize": 18 } },
  "legend": { "bottom": 10 },
  "xAxis":  { "axisLabel": { "rotate": 45, "color": "#555" } },
  "yAxis":  { "splitLine": { "lineStyle": { "type": "dashed" } } },
  "series": [
    { "itemStyle": { "borderRadius": [4, 4, 0, 0] }, "label": { "show": true, "position": "top" } }
  ]
}

Gli elenchi si uniscono per posizione: il primo elemento di "series" modifica la prima serie, il secondo la seconda. Per toccare solo la seconda: "series": [ {}, { … } ]. I colori scritti in optionOverrides valgono sopra la palette e sopra il tema scuro.

Dai flow si può solo passare dal tema chiaro a quello scuro (ECH/Chart/ToggleTheme, senza salvare): non c'è un nodo che cambi lo stile.

Altri pannelli

  • Clic su una barra o una fetta → gli altri pannelli sanno quale elemento è stato scelto.
  • Legenda e zoom restano nel grafico: per farli arrivare ad altri pannelli si usa il flow (nodi Events On Legend Change e On Data Zoom → App Bus Emitter). Così più grafici possono condividere lo zoom.
  • Al contrario, un elemento scelto altrove si evidenzia nel grafico, e un flow può chiedere di ricaricare i dati.

Problemi comuni

  • Messaggio informativo al posto del grafico. Mancano sia dataSource sia template.
  • Grafico vuoto. Il mapping punta a colonne che non esistono (maiuscole comprese), oppure la query è rifiutata perché non sei amministratore.
  • Errore con un indirizzo esterno. Il sito non permette la lettura da altre pagine (CORS), oppure il foglio Google non è pubblico.
  • Esportare l'immagine. Pulsante Esporta PNG: l'immagine è a doppia risoluzione.
