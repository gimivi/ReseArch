Timeline (TML): personalizzare lo stile beta

L'aspetto di una timeline si decide con file CSS che metti accanto al file del modello. Puoi cambiare solo qualche colore oppure ridisegnare ogni parte: asse, corsie, eventi, periodi, epoche, cursore, tooltip. I dati non contengono stili: indicano solo classi e tag.

Come funziona

  • Il tuo CSS è il terzo strato. Puoi indicare più file: si applicano nell'ordine in cui li scrivi.
  • Vale solo nel pannello della timeline: non tocca la dashboard né un'altra timeline aperta con un altro tema.
  • Hai due livelli di controllo, che puoi mescolare:
    • variabili --tml-*: semplici e stabili. Bastano per colori, font, bordi e opacità;
    • selettori sulle singole parti (classi tml-* e vis-*): controllo completo di forme, spaziature, ombre, immagini, animazioni.

E Bootstrap?

La timeline è quasi del tutto svincolata da Bootstrap: ha le sue variabili e i suoi colori. L'unico legame automatico è il font.

Cosa della timeline dipende da Bootstrap
AspettoLegato a Bootstrap?
Colori (sfondo, item, griglia, corsie…)No: valori fissi in css/TML.css.
FontSì: --tml-font vale inherit, quindi la timeline usa il font della dashboard (Titillium Web). Se ne scegli uno tuo, il legame sparisce.
Dimensione del testoNo: 13px fissi (--tml-font-size).
TooltipNo: è quello di vis-timeline, non quello di Bootstrap.
Classi di Bootstrap sui dati (bg-primary, text-danger…)Non si possono usare: una classe dei dati diventa sempre tml-c-<nome>.
Tema scuroNo: si fa con un CSS (ricetta Tema scuro).
Variabili --bs-* nel tuo CSSSì, in lettura: arrivano per ereditarietà dalla pagina.

Per legare la timeline ai colori della piattaforma basta passare le variabili di Bootstrap a quelle della timeline:

.tml-root {
    --tml-bg:          var(--bs-body-bg);
    --tml-text:        var(--bs-body-color);
    --tml-border:      var(--bs-border-color);
    --tml-item-bg:     var(--bs-primary-bg-subtle);
    --tml-item-border: var(--bs-primary);
    --tml-item-text:   var(--bs-primary-text-emphasis);
    --tml-group-bg:    var(--bs-tertiary-bg);
}

Nel tuo CSS :root indica la radice della timeline, non la pagina. Scrivere :root { --bs-primary: … } non cambia la dashboard: vale solo dentro il pannello.

Preparare il file

La configurazione della timeline sta nel modello di configurazione: il modello il cui mod_spec contiene view, layers, layerMode, css o cssText. Di solito è un modello Nessun file creato apposta, con il nome che preferisci. Il CSS si indica in tre modi, anche insieme (si applicano in quest'ordine, a parità di regola vince l'ultimo):

  1. Un modello che è il file CSS. Carica il .css e crea un modello che lo usa come file (es. temi/teatri.css), collegato all'oggetto: si applica sempre, senza scrivere nulla nel mod_spec.
  2. Il nome del file, cercato nella cartella del modello di configurazione: 
    "css": ["cronologia.css", "mostra.css"]
    Solo nomi di file: niente percorsi, niente ../, estensione .css. Più timeline della stessa cartella possono usare lo stesso CSS.
  3. Il CSS scritto nel mod_spec, per poche regole (una stringa o un elenco di righe): 
    "cssText": [
  ".tml-c-scomparso { opacity: .6 }",
  ".tml-c-incerta { border-style: dashed }"
]

Il file .css si scrive con un editor qualsiasi (VS Code, Blocco note…), in UTF-8. Se un file manca o ha un nome non ammesso, un avviso compare nel footer e la timeline usa la sola base.

CSS per livello

Con più livelli ogni livello può avere i suoi CSS (css e cssText), nella stessa cartella. Si accendono e spengono insieme al livello.

"css": ["comune.css"],
"layers": {
  "rossi":   { "label": "Archivio Rossi",   "css": ["rossi.css"] },
  "bianchi": { "label": "Archivio Bianchi", "cssText": ".tml-t-box { border-style: dashed }" }
}

Mentre lavori

  • Nel menu a destra Ricarica CSS rilegge i file senza cache: modifichi, ricarichi il file nella cartella, premi la voce. Non serve riaprire il pannello.
  • Nello stesso menu c'è un interruttore per ogni file (attivo / spento): utile per confrontare due temi.

Le classi

Il modulo mette sugli elementi della timeline classi stabili, ricavate dai dati. Sono il modo sicuro per colpire una parte precisa.

Come si scrivono i nomi

Nomi, tag e id diventano minuscoli, senza accenti; ogni altro carattere diventa un trattino. "Età del Bronzo" → .tml-c-eta-del-bronzo; "Arte/Scienza" → .tml-c-arte-scienza.

{ "id": "e7", "type": "range", "start": "1508", "end": "1512",
  "content": "Volta della Sistina", "group": "opere",
  "class": ["affresco"], "tags": ["roma", "papato"] }

Questo periodo porta: tml-t-range tml-c-affresco tml-tag-roma tml-tag-papato tml-g-opere. Nei fogli Google più classi o più tag si separano con | (affresco|restauro). I colori delle celle del foglio non arrivano alla timeline.

  • Il testo di ogni evento sta in .vis-item-content (spaziatura di base 3px 6px).
  • Le classi di un evento (tml-c-*, tml-tag-*, tml-t-*…) stanno su tutti i suoi elementi: in un box sono sul riquadro, sulla linea e sul punto. Per colpirne uno solo combina: .vis-line.tml-c-guerra.
  • Le classi di un gruppo stanno sull'etichetta e sulla riga: .vis-label.tml-g-opere colpisce solo l'etichetta. Le variabili messe sulla riga passano anche agli eventi della corsia.

Le classi vis-* sono della libreria (vis-timeline 8.5.4): funzionano, ma un aggiornamento può cambiarle. Dove basta, usa le classi tml-* e le variabili.

Un font tuo (anche da Google Fonts)

Un font da Google Fonts o da altri siti non si può collegare: @import e gli indirizzi esterni vengono tolti (vedi Cosa viene tolto). Il font va scaricato e caricato accanto al CSS.

  1. Scarica il font in .woff2. Il caricamento file accetta .woff2, non .ttf, e lo ZIP di Google Fonts contiene solo .ttf. Due strade:
    • il sito google-webfonts-helper (gwfh.mranftl.com): scegli il font e scarichi i .woff2;
    • apri nel browser un indirizzo come https://fonts.googleapis.com/css2?family=Cinzel:wght@400;700&display=swap: compaiono i link ai .woff2, scarica quelli del blocco latin.
  2. Rinomina i file con un nome fatto solo di lettere, cifre, -, _ e ., per esempio Cinzel-400.woff2 e Cinzel-700.woff2.
  3. Caricali nella cartella del CSS, o in una sua sottocartella. Se usi cssText, nella cartella del modello di configurazione.
  4. Dichiara il font e assegnalo con --tml-font, che vale per eventi, corsie e asse:
@font-face {
    font-family: "Cinzel ReseArch";
    font-weight: 400;
    font-display: swap;
    src: url("Cinzel-400.woff2") format("woff2");
}
@font-face {
    font-family: "Cinzel ReseArch";
    font-weight: 700;
    font-display: swap;
    src: url("Cinzel-700.woff2") format("woff2");
}

.tml-root { --tml-font: "Cinzel ReseArch", Georgia, serif; }

L'indirizzo in url(...) è relativo alla cartella del CSS. Una sottocartella va bene (url("font/Cinzel-400.woff2")), un percorso che esce dalla cartella no.

Solo su alcune parti. Invece della variabile usa font-family su una classe:

/* solo le etichette delle corsie */
.vis-label .vis-inner { font-family: "Cinzel ReseArch", serif; }
/* solo gli eventi del livello "rossi" */
.tml-l-rossi { font-family: "Cinzel ReseArch", serif; }

Con cssText funziona allo stesso modo. Usa l'elenco di righe e le virgolette semplici, così non devi scrivere \" nel JSON:

"cssText": [
  "@font-face { font-family: 'Cinzel ReseArch'; font-weight: 400; src: url('Cinzel-400.woff2') format('woff2'); }",
  ".tml-root { --tml-font: 'Cinzel ReseArch', serif; }"
]
  • Dai al font un nome tuo. @font-face vale per tutta la pagina: un nome comune (es. solo "Cinzel") potrebbe scontrarsi con quello di un'altra timeline o di un altro pannello.
  • Il font non compare. Il nome del file in url(...) è diverso da quello caricato, oppure il file non è nella cartella giusta. Un indirizzo esterno diventa none e il footer avvisa delle parti tolte; un nome sbagliato invece non dà avvisi. Controlla nella scheda Rete del browser che il .woff2 venga scaricato.

Evidenziare da un flow

Il nodo TML/Item/SetClass (op = add, remove o set) cambia le classi di un evento mentre la timeline è aperta. Il CSS decide l'aspetto:

/* classe "evidenza" aggiunta dal flow */
.tml-c-evidenza {
    --tml-item-bg: #fde047; --tml-item-border: #a16207;
    animation: research-tml-pulse 1.2s ease-in-out 3;
}
@keyframes research-tml-pulse {
    50% { box-shadow: 0 0 0 6px rgba(234, 179, 8, 0.35); }
}

Come per i font, dai a @keyframes un nome che non si confonda con altri.

Temi alternativi

Metti nel mod_spec più file, per esempio "css": ["base.css", "mostra.css"], dove mostra.css cambia solo ciò che serve per una presentazione. Si accendono e spengono:

  • a mano, dagli interruttori nel menu a destra;
  • da un flow, con TML/Theme/SetActive (name = nome del file, widget active); TML/Theme/List dice quali sono accesi.

All'apertura tutti i file di css sono accesi; quelli dei livelli seguono la visibilità del livello.

Eventi attenuati da un filtro

/* più tenui e in grigio invece della sola trasparenza */
.tml-root { --tml-filtered-opacity: 0.4; }
.tml-filtered-out { filter: grayscale(1); }

Vale con i filtri in modo "attenua" (mode: "dim" di TML/Filter/Apply); in modo "nascondi" gli eventi spariscono.

Cosa viene tolto, e perché

Confinato al pannello

Prima di applicarlo, il modulo racchiude il tuo CSS dentro la radice della timeline:

/* quello che scrivi */            /* quello che arriva alla pagina */
.tml-c-guerra { … }                .tml-root[data-css-scope="3"] {
                                       .tml-c-guerra { … }
                                   }
  • .tml-root e :root nel tuo file indicano la radice stessa della timeline.
  • Una regola su body, .navbar o altre parti della dashboard non colpisce nulla.
  • @media e @supports funzionano dentro il confinamento. @font-face, @keyframes, @property e @counter-style restano fuori e valgono per la pagina: usa nomi distintivi.
  • Il meccanismo usa il CSS annidato: serve un browser aggiornato (dal 2024 in poi).

Ogni parte tolta viene sostituita (un url diventa none) e il footer avvisa: "tema.css: 2 parti tolte (import, indirizzi esterni o codice)". Il motivo: un indirizzo esterno farebbe partire richieste verso server di terzi a ogni apertura della timeline.

Quale regola vince

Il confinamento aggiunge peso ai tuoi selettori: .tml-c-guerra diventa .tml-root[data-css-scope] .tml-c-guerra e vince sulle regole semplici della base. Restano alla pari alcune regole della base con più classi, come .vis-item.vis-selected o .vis-item.vis-point.

  • Con le variabili il problema non c'è: la base legge var(--tml-item-bg) e trova il valore che hai messo sull'elemento.
  • Se scrivi proprietà dirette e una regola non vince, aggiungi una classe al selettore (.vis-item.tml-c-guerra). !important solo come ultima risorsa: blocca anche il colore del selezionato.

Problemi comuni

  • Il CSS non si applica. Il file non è nella cartella del modello di configurazione, o il nome in css è scritto diversamente (maiuscole comprese). Guarda gli avvisi nel footer.
  • Ho cambiato il file ma non vedo differenze. Usa Ricarica CSS nel menu a destra: rilegge senza cache.
  • Una classe non ha effetto. Controlla come diventa il nome (minuscole, niente accenti, trattini): "Età d'oro" → .tml-c-eta-d-oro.
  • Una regola non vince. Usa una variabile, oppure rendi il selettore più preciso (sezione Cosa viene tolto).
  • Il font non si vede. Il file .woff2 deve stare nella cartella del CSS e l'url deve essere relativo. Un indirizzo esterno, anche di Google Fonts, viene tolto: vedi la ricetta Un font tuo.
  • L'immagine non compare. Stesso motivo: solo indirizzi relativi alla cartella del CSS.
  • Box, linea e punto hanno colori diversi. Hai colorato un solo elemento con una proprietà diretta: usa le variabili --tml-item-*, che valgono per tutti e tre.
  • Gli eventi si sovrappongono dopo aver acceso un tema. Se un tema cambia font o spaziature, la timeline può tenere le misure vecchie finché non si ridisegna: usa Ricarica oggetto.
  • Il testo di un periodo breve esce dal riquadro. È voluto (leggibile invece che tagliato). Per tagliarlo: .vis-item.vis-range .vis-item-overflow { overflow: hidden; }
  • I colori del foglio Google non arrivano. Il foglio porta solo classi e tag: i colori stanno nel CSS.
