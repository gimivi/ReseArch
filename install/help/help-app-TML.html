Timeline (TML) beta

TML disegna una linea del tempo con eventi, periodi ed epoche, divisi in corsie, anche prima di Cristo. Si zooma dai millenni ai giorni. Serve per cronologie di cantiere, biografie, storia di un edificio o di un territorio.

In entrambi i casi lo stile (colori, forme) sta nei CSS, non nei dati.

Dove si scrive come mostrare i dati

Le chiavi view, css, cssText, layerMode e layers vanno nel mod_spec di un solo modello dell'oggetto: TML lo riconosce dal contenuto, l'ordine dei modelli non conta. Di solito è un modello "Nessun file" dedicato (es. "Timeline – configurazione").

  • Se più modelli hanno queste chiavi vale il più vecchio, e in basso compare un avviso.
  • Se nessuno le ha, la vista si adatta ai dati.

Dati in un file — template "Timeline — Base" base

Il file del modello (.json)

{
  "groups": [
    { "id": "persone", "content": "Persone", "nested": ["artisti"], "open": true },
    { "id": "artisti", "content": "Artisti" }
  ],
  "items": [
    { "id": "e1", "start": "1452-04-15", "end": "1519-05-02", "content": "Leonardo",
      "group": "artisti", "class": ["3"], "tags": ["arte"], "title": "Vinci – Amboise" },
    { "id": "e2", "start": "1503", "content": "Gioconda", "type": "point", "group": "artisti" }
  ]
}
  • groups: le corsie. nested elenca le sotto-corsie, open le mostra aperte.
  • items: gli elementi. id stabile, start obbligatorio, end per i periodi, content il testo, title la nota al passaggio del mouse, class e tags per lo stile.
  • type: "box" evento (predefinito senza fine), "point" punto, "range" periodo (predefinito con fine), "background" fascia d'epoca dietro le corsie.

La spec: come mostrarli

{
  "view": { "start": null, "end": null, "zoomMax": "5000y", "orientation": "top",
            "stack": true, "era": "auto", "cursor": null },
  "css": []
}
Campi di view
CampoEffetto
start, endPeriodo visibile all'apertura; null = tutti gli elementi.
min, maxLimiti oltre i quali non si può scorrere.
zoomMin, zoomMaxZoom minimo e massimo come durate: "30min", "1d", "5000y".
orientationAsse delle date in alto ("top") o in basso ("bottom").
stackElementi sovrapposti messi uno sotto l'altro.
eraIndicazione a.C./d.C.: "auto" solo se serve, "always", "never".
cursorData di una linea verticale di riferimento; null = nessuna.

Un esempio completo è nei file di installazione della piattaforma (install/esempi/tml-esempio.json).

Date

  • Forme ammesse: "1492", "1492-10", "1492-10-12", "1492-10-12T08:30". Un numero intero vale come anno.
  • Prima di Cristo: anno negativo, "-753" = 753 a.C. L'anno 0 non esiste.

Dati da Google Sheets base

Un modello senza file per ogni scheda del documento. Il documento va condiviso con "Chiunque abbia il link" in lettura.

{ "spreadsheetId": "1BxiMVs0…upms", "gid": "0", "role": "items", "layer": "rossi", "limit": 1000 }
Schede di un documento Google per TML
TemplateroleColonne (prima riga)
Foglio Google (eventi)"items" id, tipo (punto, evento, periodo, epoca), inizio, fine, etichetta, nota, gruppo, classi, tag, obj_id
Foglio Google (gruppi)"groups" id, etichetta, padre, ordine, aperto (sì/no), visibile (sì/no), classi, nota
Foglio Google (epoche)"eras" id, inizio, fine, etichetta, nota, classi, gruppo (per limitarla a una corsia)
  • spreadsheetId e gid: dall'indirizzo del foglio, come per l'App GSH.
  • layer: nome del livello; tutte le schede dello stesso documento hanno lo stesso.
  • mapping (facoltativo): se le colonne hanno altri nomi, es. { "start": "Data" }.
  • Più valori in una cella (classi, tag) si separano con |. Le colonne in più finiscono nei dati dell'evento.
  • Collega tutti i modelli-foglio allo stesso oggetto TML. Un foglio che non si legge non blocca gli altri: compare un avviso in basso.
  • La vista e lo stile stanno nel modello di configurazione (vedi Due strade), che può essere un modello "Nessun file".

Importante: prima di scrivere le date, metti le colonne inizio e fine in Formato → Numero → Testo normale. Altrimenti Google le trasforma e gli anni a.C. si perdono.

Più livelli — template "Timeline — Livelli" avanzato

Per mettere sulla stessa linea del tempo due o più fonti (es. due archivi) con zoom e cursore comuni. La spec va nel modello di configurazione (di solito un modello "Nessun file"):

{
  "view": { "zoomMax": "5000y", "era": "auto", "orientation": "bottom" },
  "css": [],
  "layerMode": "stack",
  "layers": {
    "rossi":   { "label": "Archivio Rossi",   "css": [], "visible": true, "open": false },
    "bianchi": { "label": "Archivio Bianchi", "css": [], "visible": true, "open": false }
  }
}
  • layerMode: "stack" livelli uno sotto l'altro; "merge" fusi, con le corsie dello stesso nome unite (per confrontare cronologie). Si cambia anche dal menu del pannello.
  • layers: per ogni livello etichetta, CSS propri (css, cssText), visibilità iniziale (visible) e open: con false il livello parte chiuso in una riga, e si apre con un clic sul nome. I livelli si accendono e spengono dal menu a sinistra.
  • Con più livelli gli id diventano livello:id (es. rossi:cesare) nei flow e negli scambi con gli altri pannelli.

Colori e stile

  • Senza CSS ci sono 12 colori pronti: metti "class": ["1"] … ["12"] (nei fogli: colonna classi = 1 … 12).
  • Per uno stile tuo ci sono tre modi, anche insieme. Valgono solo in questo pannello:
    • Modello con un file .css collegato all'oggetto: si applica sempre.
    • "css": ["cronologia.css"] nel modello di configurazione: nomi di file nella cartella di quel modello.
    • "cssText": il CSS scritto direttamente nel mod_spec (testo, o elenco di righe).
  • Classi utili: .tml-c-<classe>, .tml-g-<gruppo>, .tml-tag-<tag>, .tml-l-<livello>, .tml-t-range (tutti i periodi), .tml-root (variabili --tml-*). Esempio: install/esempi/tml-esempio.css.
  • Tutti i dettagli (variabili, parti della timeline, ricette, cosa viene tolto) sono nella guida Timeline, stile CSS.

Problemi comuni

  • Eventi a.C. finiti nel posto sbagliato. Le celle data del foglio non sono in "Testo normale".
  • Un evento non compare. Manca id o start/inizio, oppure due eventi hanno lo stesso id.
  • Il CSS non si applica. Il file non è nella cartella del modello di configurazione, o il nome in css è scritto diversamente.
  • La vista non è quella scritta nel mod_spec. Più modelli hanno view, css o layers: vale il più vecchio (avviso in basso). Lascia queste chiavi in un solo modello.
  • Corsia con un nome strano. Un evento cita un gruppo che non c'è nel foglio dei gruppi: diventa una corsia con l'id come nome.
